快速上手

WPF 项目只能在 Windows 上构建，需要 .NET 8 SDK：

git clone https://github.com/EukaryDeveloper/Eukary-Launcher.git
cd Eukary-Launcher
dotnet build EukaryLauncher.sln -c Debug
dotnet run --project EukaryLauncher.App

# 纯逻辑断言（不需要网络，秒级，改完就跑）
dotnet run --project EukaryLauncher.Smoke

# 端到端：真下载 + 真启动 1.20.4
dotnet run --project EukaryLauncher.Smoke -- --launch 1.20.4

项目结构

项目职责硬性约束
EukaryLauncher.Core清单解析、下载、安装、参数拼装、进程启动、加载器元数据零 UI 依赖，路径规则集中在 GamePaths
EukaryLauncher.AppWPF 界面、ViewModel、下载队列、设置持久化颜色 / 圆角 / 字号 / 间距只从 Themes/Tokens.xaml 取
EukaryLauncher.Smoke纯逻辑断言 + 端到端下载 / 启动纯逻辑部分必须秒级、不联网

判断代码该放哪：能不能在没有窗口的机器上跑通？能，就属于 Core。新能力优先在 Core 里做成可测的服务，UI 层只负责喂参数和显示进度。

分支版本

main 是唯一主干，永远保持可构建，不直接推送，一律走 Pull Request。功能开发请按以下方式建分支：

类型格式示例
功能feat/<里程碑>-<简述>feat/m2-msa-login
修复fix/<简述>fix/authcodecheck-403-fallback
文档 / 杂项docs/、chore/docs/website

提交信息直接用一句中文说清做了什么，不加 feat: / fix: 前缀——仓库首页文件列表会显示每个文件最后一条提交信息，干净的可读性比形式化标记更重要。

常见扩展点

二次开发指南里给了每种扩展的完整步骤，这里列一个速查：

  • 给下载页加一个标签 —— 新建 TabViewModel + View，注册 DataTemplate，三处同步改 DownloadsViewModel
  • 支持一种新的模组加载器 —— 从 LoaderService 识别到安装 Job、Smoke 断言共 7 步
  • 加一个设置项 —— LauncherSettings 加属性，并且一定要接到启动 / 安装链路上
  • 加一个主页面 —— NavPage 枚举、导航项、页面轨道三处保持顺序一致
  • 加一个下载源 —— 实现 IMirrorService 六个 URL 变换，注册到 MirrorFactory.All
改视觉只动 Themes/Tokens.xaml；新样式组追加到 Controls.xaml 末尾——资源字典里的前向引用会让整个应用启动即崩。

插件开发

插件系统在项目路线图中（里程碑 M8），目标是让插件像细胞器一样自由挂载在启动器核心之上，目前尚未开放正式的插件 API。

在插件系统落地之前，参与的方式是分支二次开发：Fork 仓库、按上面的分支规范建分支，在 Core 层新增可测服务、在 App 层接 UI。Core 类库本身零 UI 依赖、职责边界清晰，就是按"未来可拆分为插件宿主"的方向设计的——现在按约定写的扩展代码，之后迁移到插件形态的成本会很低。

想做插件方向的功能但拿不准接口形态，欢迎到 Discussions 先聊。

  • ❌ 打包 / 分发 Minecraft 游戏本体文件
